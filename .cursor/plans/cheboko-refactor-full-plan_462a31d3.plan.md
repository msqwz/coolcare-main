## Цель

Переделать текущий проект в продукт под компанию «Чебоко» (сервис и обслуживание кофе-машин в Ростове-на-Дону), сохранив существующую архитектуру (FastAPI + Supabase + два фронтенда на React/Vite), но адаптировав:

- бизнес-логику заявок под кофе-машины,
- структуру данных (клиенты, точки, оборудование, заявки),
- интерфейсы мастера (PWA) и админ-панели,
- брендирование и тексты,
- отчётность и уведомления.

## 1. Анализ текущей модели и бизнес-требований

- **1.1. Проанализировать текущие сущности и таблицы Supabase**
  - Изучить миграции в [backend/migrations/supabase_schema.sql](backend/migrations/supabase_schema.sql): таблицы `users`, `jobs`, `dashboard`-данные, `push_subscriptions` и др.
  - Понять текущую структуру `jobs` (заявок): какие поля есть (адрес, статус, исполнитель, время и т.п.).
- **1.2. Зафиксировать бизнес-процесс «Чебоко»** (вне кода, в документации)
  - Как поступают заявки: звонок, сайт, постоянные контракты.
  - Типы заявок: установка, плановое ТО, ремонт, чистка, настройка, аварийный вызов.
  - Жизненный цикл заявки: от создания до закрытия (включая «ожидание запчастей»).
  - Роли: мастер, диспетчер/оператор, администратор.
- **1.3. Определить основные сущности для кофе-сервиса**
  - Клиент (юрлицо/точка сети).
  - Локация/точка установки (адрес, контакт на месте).
  - Кофе-машина (модель, бренд, серийный номер, дата установки, история ТО).
  - Заявка на обслуживание (привязана к машине и точке, содержит симптомы, фотографии, материалы).

## 2. Проектирование новой доменной модели

- **2.1. Спроектировать таблицы Supabase под «Чебоко»**
  - Добавить/скорректировать таблицы:
    - `clients` — клиенты (название, ИНН/реквизиты, контакты).
    - `locations` — точки обслуживания (адрес, клиент, координаты, контакт на месте).
    - `machines` — кофе-машины (бренд, модель, серийный номер, тип, дата установки, статус, привязка к location).
    - `service_jobs` (или модифицировать `jobs`) — заявки на обслуживание (тип работы, приоритет, статус, назначенный мастер, дата/время, описание проблемы, ссылка на `machine_id`, `location_id`).
    - `service_materials` — материалы/запчасти, использованные в заявке.
    - `service_contracts` (опционально) — абоненты/контракты ТО.
  - Продумать связи/ограничения: foreign keys, каскадное удаление, индексы по `client_id`, `location_id`, `machine_id`, `assigned_user_id`, датам.
- **2.2. Обновить Pydantic-схемы backend**
  - В [backend/schemas.py](backend/schemas.py):
    - Добавить/изменить схемы под новые сущности (`Client`, `Location`, `Machine`, `ServiceJob`, `Material` и DTO для фронта).
    - Сохранить обратную совместимость, если старые API пока нужны (или подготовить миграционный переходный период).
- **2.3. Определить статусы и типы работ**
  - Статусы заявок: `new`, `assigned`, `in_route`, `on_place`, `waiting_parts`, `completed`, `cancelled`.
  - Типы работ: `install`, `maintenance`, `repair`, `cleaning`, `setup`, `emergency`.
  - Оформить их в константах ([shared/constants.js](shared/constants.js)) для единообразного использования фронтом и бэкендом.

## 3. Адаптация backend под домен «Чебоко»

- **3.1. Обновить/создать роуты для работы с сущностями**
  - В `backend/routers`:
    - Добавить новые роутеры: `clients_router`, `locations_router`, `machines_router`, `service_jobs_router` (или расширить существующий `jobs_router`).
    - Эндпоинты CRUD: создание/редактирование клиентов, точек, машин, заявок, материалов.
  - Обновить [backend/main.py](backend/main.py), чтобы подключить новые роутеры.
- **3.2. Логика назначения и планирования**
  - В роутере заявок реализовать:
    - Назначение мастера на заявку (вручную и, по возможности, с подсказками по гео/загруженности).
    - Перенос заявки (смена даты/времени, уведомление мастеру).
    - Ведение статусов (с контролем допустимых переходов: например, нельзя «выполнена» без «на месте»).
- **3.3. Интеграция с уведомлениями**
  - Использовать уже существующий [backend/routers/push_router.py](backend/routers/push_router.py) и [backend/push_service.py](backend/push_service.py):
    - Отправка уведомлений мастеру при новой заявке, изменении статуса, напоминания о плановом ТО.
  - При необходимости, расширить `push_service` для разных типов уведомлений (текст, заголовок, иконка, тип события).
- **3.4. Отчёты и аналитика**
  - В `dashboard_router` (или новом роутере) реализовать:
    - Сводки по заявкам: за день/неделю/месяц, по клиентам, по мастерам.
    - SLA: среднее время реакции, среднее время выполнения.
    - Нагрузку мастеров (кол-во заявок в работе, выполненных, просроченных).

## 4. Адаптация PWA (приложение мастера, `frontend`)

- **4.1. Брендинг и UI под «Чебоко»**
  - В `frontend/public/manifest.json`, `index.html`, стилях (`src/styles/*.css`):
    - Заменить название, описание, цвета, иконки на бренд «Чебоко».
    - Обновить логотипы и favicon.
- **4.2. Карточка заявки под кофе-машины**
  - В компонентах заявок (страницы/компоненты в `frontend/src/components` и `src/pages`):
    - Добавить отображение модели, бренда, серийного номера кофе-машины, истории обращений.
    - Поля для ввода симптомов, предпринятых действий, результатов (что заменено, что настроено).
    - Возможность прикреплять фото (интеграция с Supabase Storage или другим хранилищем).
- **4.3. Карта и маршруты в Ростове**
  - На карте (сейчас используется Яндекс-карта) отрисовывать:
    - Точки клиентов/машин.
    - Маршрут мастера по заявкам на день.
  - Добавить фильтры по статусам и времени (например, только сегодняшние заявки).
- **4.4. Личный кабинет мастера**
  - В `ProfileTab` и связанных компонентах:
    - Показать персональную статистику мастера (сколько заявок выполнено, среднее время, рейтинг).
    - Параметры уведомлений (новые заявки, напоминания, изменения статуса).
- **4.5. Офлайн-режим и чек-листы**
  - Использовать существующую offline-инфраструктуру (`frontend/src/offlineStorage.js`) для хранения:
    - Черновиков отчётов по заявкам.
    - Фото/заметок, которые синхронизируются при появлении сети.
  - Добавить чек-листы для ТО/ремонта (структурированные шаги), чтобы мастер мог отмечать выполненное.

## 5. Адаптация админ-панели (dispatcher)

- **5.1. Брендинг и навигация**
  - Обновить название, логотип, цвета под «Чебоко» в `dispatcher/index.html`, `src/App.jsx`, общих компонентах.
- **5.2. Справочники и управление данными**
  - Страницы/разделы:
    - Клиенты (список, карточка клиента, связанные точки и машины).
    - Точки (адреса, контакты, список машин, история заявок).
    - Кофе-машины (модели, статусы, история ТО/ремонтов).
  - Реализовать эти разделы в `dispatcher/src/pages` и `src/components` с использованием API backend.
- **5.3. Работа с заявками**
  - Расширить текущую страницу заявок:
    - Фильтры по клиенту, машине, типу работы, статусу, мастеру.
    - Визуальный «борд» статусов (канбан: новые → назначены → в работе → ожидание запчастей → выполнены).
  - Возможность быстро создавать заявки из карточки клиента/машины.
- **5.4. Планирование и расписание мастеров**
  - Раздел «Мастера/расписание»:
    - Привязка смен/графиков мастеров.
    - Вид календаря с занятостью по дням.
- **5.5. Отчётность**
  - В `dispatcher` создать дашборды:
    - Сводка по заявкам, ТО, ремонту.
    - Рабочие отчёты по клиентам (для договоров/актов).

- **6.2. Telegram-бот (опционально)**
  - Адаптировать [backend/telegram_bot.py](backend/telegram_bot.py) под сценарии «Чебоко»:

    - Возможность мастера подтвердить получение/начало выезда через бот.
- **6.3. Уведомления для клиентов (опционально на следующий этап)**
